Từ một container đến một đám mây nhỏ

Một ứng dụng, một môi trường riêng. Khám phá cách Docker biến những dịch vụ độc lập thành nền móng cho MyMiniCloud.

13Nhóm 13·MyMiniCloud Journal

Container giải quyết điều gì?

“Trên máy mình vẫn chạy” là một tình huống quen thuộc khi đưa ứng dụng từ môi trường này sang môi trường khác. Phiên bản thư viện, cấu hình hệ thống hay một file bị thiếu đều có thể làm kết quả thay đổi. Docker giúp đóng gói ứng dụng và các thành phần cần thiết thành một image, để có thể tạo những môi trường chạy nhất quán hơn.

Image là bản đóng gói; container là một phiên bản đang chạy từ image đó. Một image có thể tạo ra nhiều container. Đây cũng là ý tưởng phía sau hai Web Server của MyMiniCloud: dùng chung một image, nhưng có dấu nhận diện khác nhau để quan sát khi cân bằng tải.

Hình dung đơn giản: image giống một bản thiết kế, còn container là một phiên bản được dựng lên từ bản thiết kế ấy. Dừng container không đồng nghĩa với xóa image.

Ghép các dịch vụ bằng Compose

Một website có thể cần Web Server, API, cơ sở dữ liệu và nơi lưu tệp. Thay vì ghi nhớ nhiều lệnh khởi chạy, Docker Compose mô tả các dịch vụ trong một file YAML. Mỗi service có image, cổng, biến môi trường và cấu hình lưu trữ riêng.

Trong MyMiniCloud, Web Server phục vụ nội dung tĩnh ở cổng 80 bên trong container. Máy tính của người dùng truy cập qua cổng 8080. Hai con số có vai trò khác nhau:

DOCKER COMPOSE
ports:
  - "8080:80"

Phía trái là cổng trên máy host; phía phải là cổng của container. Trình duyệt mở http://localhost:8080/, còn một container khác trong mạng gọi http://web-frontend-server:80/.

Một mạng chung, nhiều vai trò

Các service tham gia mạng cloud-net có thể tìm nhau bằng tên service. Nhờ vậy, cấu hình không cần phụ thuộc vào địa chỉ IP container có thể thay đổi sau mỗi lần tạo lại.

  • Web Server: cung cấp trang chủ, blog, hình ảnh và CSS.
  • Application Server: xử lý API và logic ứng dụng.
  • Object Storage: quản lý bucket và tệp thông qua API tương thích S3.

Việc tách vai trò giúp phát triển từng phần độc lập. Blog tĩnh có thể hoàn thiện trước khi API sẵn sàng; MinIO cũng có thể kiểm thử upload và download riêng.

Bắt đầu từ những phần nhỏ

Trong giai đoạn đầu, chỉ khởi động các service đang làm sẽ giúp kiểm tra lỗi dễ hơn. Lệnh dưới đây chạy riêng Web và Storage trong dự án:

POWERSHELL / BASH
docker compose up -d --build --no-deps web-frontend-server object-storage-server

Sau đó, kiểm tra trạng thái bằng docker compose ps, mở trang web và đọc log khi có lỗi. Khi từng thành phần đã hoạt động đúng, bước ghép hệ thống sẽ tập trung vào kết nối và luồng request thay vì sửa nhiều lỗi cùng lúc.

Điều đáng nhớ không chỉ là lệnh khởi chạy, mà là mối quan hệ giữa image, container, cổng và mạng. Nắm chắc bốn khái niệm này, bạn đã có nền tảng để đọc phần lớn cấu hình của MyMiniCloud.
