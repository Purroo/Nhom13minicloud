Đường đi của một request: từ trình duyệt đến Nginx

Theo dấu một yêu cầu HTTP để hiểu cách trang chủ, đường dẫn /blog/ và những tài nguyên tĩnh được đưa đến người đọc.

13Nhóm 13·MyMiniCloud Journal

Một địa chỉ, một yêu cầu

Khi bạn nhập địa chỉ một website và nhấn Enter, trình duyệt gửi một yêu cầu HTTP đến máy chủ. Yêu cầu chứa đường dẫn cần đọc, chẳng hạn / hoặc /blog/. Máy chủ trả về mã trạng thái, các header và nội dung phù hợp.

Trong phần Web của MyMiniCloud, Nginx nhận yêu cầu và trả về file HTML. Sau khi đọc HTML, trình duyệt tiếp tục yêu cầu CSS, JavaScript và ảnh. Vì vậy, một trang đẹp cần nhiều tài nguyên cùng được phục vụ đúng đường dẫn.

Nginx tìm file như thế nào?

Cấu hình root chỉ ra thư mục gốc chứa nội dung. Với root /usr/share/nginx/html;, đường dẫn /assets/style.css tương ứng với file trong thư mục assets dưới root. Chỉ thị index index.html; chọn file mặc định khi người đọc mở một thư mục.

NGINX
root /usr/share/nginx/html;
index index.html;

location / {
    try_files $uri $uri/ =404;
}

try_files kiểm tra lần lượt file, thư mục rồi trả 404 nếu không tìm thấy. Một đường dẫn sai cần phản hồi đúng trạng thái 404 để người dùng và công cụ kiểm thử nhận biết được lỗi.

Hiểu đúng về alias

alias thay thế phần đường dẫn đã khớp với location bằng một thư mục cụ thể. Trong bài lab, toàn bộ nội dung dưới /blog/ được ánh xạ vào thư mục blog:

NGINX
location ^~ /blog/ {
    alias /usr/share/nginx/html/blog/;
    index index.html;
    autoindex off;
}

Ví dụ, /blog/blog1.html được đọc từ /usr/share/nginx/html/blog/blog1.html. Dấu gạch chéo cuối ở cả hai đường dẫn cần được giữ đúng. autoindex off giúp Nginx không tự hiển thị danh sách file trong thư mục.

Một chi tiết dễ bỏ qua: CSS dùng đường dẫn /assets/style.css sẽ hoạt động từ cả trang chủ lẫn bài viết lồng trong /blog/, vì dấu / đầu chỉ về gốc website.

Đọc kết quả HTTP

Kiểm thử bằng trình duyệt cho biết trang có hiển thị đúng hay không. Kiểm tra HTTP bổ sung bằng chứng về cách máy chủ phản hồi. Trong PowerShell, dùng curl.exe để gọi đúng công cụ curl:

POWERSHELL
curl.exe -I http://localhost:8080/
curl.exe -I http://localhost:8080/blog/

Hai địa chỉ trên cần trả 200 OK. Với /blog thiếu dấu gạch chéo cuối, máy chủ chuyển hướng đến /blog/. Một file không tồn tại cần trả 404 Not Found.

Khi ghép với gateway, trình duyệt sẽ gọi cổng 80 của gateway, rồi gateway chuyển request tới Web Server. Nội dung HTML vẫn như cũ; chỉ đường đi của request có thêm một bước. Những liên kết tính từ gốc website sẽ tiếp tục hoạt động với cách định tuyến này.
